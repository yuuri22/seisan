# 割り勘

ふたりで暮らすときの立て替えを記録して、いくら返せばいいかを出すアプリです。
レシートに個人的な買い物が混ざっていても、その分を引いてから折半します。

- HTMLファイル1つで動きます。ビルドも依存関係もありません
- 記録は端末に保存され、計算もすべて端末の中で行われます
- Supabaseをつなぐと、ふたりの端末で同じ記録が見られます（任意）
- PayPayの取引履歴CSVを、ファイルを選ぶだけで取り込めます

---

## そのまま使う

`index.html` をブラウザで開けば、それだけで使えます。
セットアップは不要です。同期を使いたくなったら、下の手順に進んでください。

# セットアップ（Claude Code に任せる）

Supabaseの用意、GitHubへの公開、アプリへの設定を、まとめて任せられます。

## あなたの手作業（3分ほど）

### 1. Supabaseに登録する

<https://supabase.com/> の「Start your project」から登録します。
プロジェクトは作らなくて構いません。Claude Codeが作ります。

### 2. アクセストークンを発行する

<https://supabase.com/dashboard/account/tokens> で「Generate new token」。
`sbp_` で始まる文字列をコピーしてください。
**この画面を閉じると二度と見られません。**

### 3. GitHub CLI で認証しておく（公開もする場合）

```bash
gh auth login
```

### 4. 二要素認証をかける

GitHubとSupabase、両方のアカウントに設定してください。
**この構成でいちばん効く対策です。** あとからでは間に合いません。

````
## 進め方の前提

- Supabase CLI はバージョンによってコマンドや引数が変わります。
  失敗したら推測で直さず、必ず `--help` で正しい書き方を確認してから進めてください。
- トークンは環境変数 SUPABASE_ACCESS_TOKEN に入れて使ってください。
  コマンドの引数に直接書くと、シェルの履歴に残ってしまいます。
- 共有キーは秘密の値です。リポジトリには絶対にコミットしないでください。

## 手順

### A. Supabase

1. `npx supabase --version` で CLI が使えるか確認する
2. トークンで認証する
3. `npx supabase orgs list` で組織IDを調べる
4. データベースのパスワードを英数字32文字でランダム生成し、
   東京リージョン（ap-northeast-1）に `warikan` という名前で
   プロジェクトを作る。作成完了まで2分ほど待つ
5. `npx supabase projects list` で project ref を取得する
6. UUIDをひとつ生成する（`node -e "console.log(crypto.randomUUID())"` など）。
   これが共有キーになります
7. supabase/migrations/20260815000000_warikan.sql の中にある
   `__HOUSEHOLD_UUID__` を、手順6のUUIDに置き換える
   ※ この変更はコミットしないこと。適用後、元の `__HOUSEHOLD_UUID__` に戻すこと
8. `npx supabase link --project-ref <ref>` で接続し、
   `npx supabase db push` で適用する
9. `npx supabase projects api-keys --project-ref <ref>` で
   anon public キーを取得する
   （service_role キーは取得も表示もしないこと）

### B. 動作確認

10. curl で warikan_pull を呼び、次の2つを試す。
    - 正しい共有キー → names と entries を含むJSONが返る
    - でたらめなUUID → "unknown key" のエラーが返る
    両方が期待どおりでなければ、原因を調べてから次に進むこと

### C. GitHub

11. `gh repo create` でリポジトリを作り（publicで構いません。
    鍵を含めないため公開しても記録は読まれません）、
    このフォルダの内容をpushする
12. git status で、__HOUSEHOLD_UUID__ を置き換えたままの
    マイグレーションがステージされていないことを必ず確認すること
13. GitHub Pages を有効にする（main ブランチの / (root)）
14. 公開URLを取得する

### D. 仕上げ

15. 次をまとめて表示してください:
    - 公開URL
    - プロジェクトURL（https://<ref>.supabase.co）
    - anon public キー
    - 共有キー
    - データベースのパスワード
    - リポジトリのURL

私の操作が必要になったら、何をすればよいか具体的に教えてください。
````

## 仕上げ（あなた）

Claude Codeが表示した値を、アプリに入れます。

1. 公開URLを開く
2. **設定 → ふたりで同期する** に3つを入力
   - プロジェクトURL
   - APIキー（anon public）
   - 共有キー
3. **同期を有効にする** をオンにする
4. **相手を招待するリンクを作る** を押す
5. コピーされたリンクを、相手に個別に送る

相手はリンクを開くだけです。入力は要りません。

# 安全性について

## 守りの要は「共有キー」ひとつです

共有キーはUUID（122ビットの乱数）で、総当たりは現実的に不可能です。
データベースのテーブルは完全に閉じてあり、
共有キーの一致を求める関数を通してのみ読み書きできます。

APIキー（anon public）は公開される前提のもので、
これだけではテーブルに一切触れません。

## リポジトリに鍵は入りません

`index.html` の `DEFAULTS` は空のままにしてください。
鍵は招待リンクで渡します。URLの `#` 以降はサーバーに送信されないため、
GitHubのログにも残りません。

`.gitignore` で、鍵を埋め込んだファイルの誤コミットも防いでいます。

## お願いしたいこと

1. **GitHubとSupabaseに二要素認証をかける** — いちばん効きます
2. **招待リンクは、ふたりだけが見られる場所で送る**
3. **心当たりのないリンクは開かない**（開いても確認画面で止まります）

詳しい検証結果は `docs/` にあります。

- `安全性の確認とSupabaseとの関係.md` — 何がどこに保存され、誰が見られるのか
- `セキュリティの確認結果.md` — データベース設計の検証
- `Basic認証は効くのか.md` — 対策を選ぶときの考え方

# UIを変える

`index.html` の先頭にある `:root{ … }` が、色・角丸・余白の定義です。
ここを1行変えるだけで、アプリ全体に反映されます。

```css
--brand: #0091FF;        /* 基調の色 */
--radius-lg: 18px;       /* カードの角丸 */
--surface-app: #F5F7FA;  /* 背景 */
```

Claude Code に頼むときは、こう伝えると崩れにくくなります。

```
index.html のUIを変更してください。
デザイントークンは :root にまとまっているので、
個別の場所を直接いじるのではなく、できるだけトークン側で調整してください。
```

大きく変えるときはブランチを切ってください。気に入らなければ捨てられます。

```bash
git switch -c ui-experiment
```

# 困ったとき

**共有キーを漏らしてしまった**

SQL Editor で新しいキーを発行し、入れ直してください。
古いキーの記録は引き継がれないので、先に控えを残しておいてください。

```sql
insert into public.households (id) values (gen_random_uuid())
returning id as "共有キー";
```

**しばらく使わずにいたら同期しなくなった**

無料枠は7日間アクセスがないと一時停止します。
Supabaseの管理画面から再開してください。記録は消えていません。
端末の記録は無事なので、その間もアプリはふつうに使えます。

**同期をやめたい**

設定のスイッチをオフにするだけです。端末の記録はそのまま残ります。

**アプリの中にも説明があります**

下の「使い方」タブに、ふだんの流れから困ったときまで載せてあります。
