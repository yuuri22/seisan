# 安全性の確認と、Supabaseとの関係

前回の確認のあとに追加した「招待リンク」と「GitHub Pagesでの公開」について、
あらためて検証しました。**問題が1つ見つかり、修正しました。**
あわせて、Supabaseが何をしているのかを整理します。

---

# 第1部：見つかった問題

## 1. 細工した招待リンクで、記録を盗まれる（重大・修正済み）

### 何が起きるか

招待リンクは、接続先と鍵をURLに埋め込んだものです。
アプリはそれを読み取って、**すぐに手元の記録を送信します**。

ここが問題でした。攻撃者が自分のSupabaseを用意し、
その接続先を埋め込んだリンクをあなたに送ったとします。

あなたがそのリンクを開くと、アプリは何も聞かずに設定を切り替え、
**あなたの記録をすべて攻撃者のサーバーへ送ってしまいます。**

「相手は開くだけでいい」という手軽さが、そのまま穴になっていました。

### どう直したか

リンクを開いたとき、次のように分けます。

| 状況 | 動き |
|---|---|
| 記録がなく、設定もまだ | そのまま適用（送るものがないので安全） |
| 記録がある、または別の設定がある | **確認画面を出す** |

確認画面には、接続先のドメインと共有キーを表示します。
「この設定を使うと、いまある○件の記録がここへ送られます」と明示し、
使うかやめるかを選べるようにしました。

心当たりのないリンクなら、そこで止められます。

---

## 2. GitHub Pages では保存領域が他のリポジトリと共通（要注意・仕様）

### 何が起きるか

`username.github.io/warikan/` で公開した場合、
ブラウザから見た「同じサイト」の単位は **`username.github.io` 全体**です。

つまり、あなたが同じアカウントで公開している**他のプロジェクトも、
このアプリの保存領域を読めます。** 共有キーも含めてです。

自分で作ったものだけを置いているなら問題ありません。
しかし、どこかから持ってきたコードを同じアカウントで公開している場合、
そのコードが鍵を読み取れる状態にあります。

### 対処のしかた

- 同じアカウントには、自分が中身を把握しているものだけを置く
- 気になるなら、独自ドメインを設定する（別のサイト扱いになります）
- あるいは、公開せずにファイルを直接渡す形にする

---

## 3. 公開すると、アプリを差し替えられる余地が生まれる（要注意・仕様）

ファイルを手渡ししていたときは、渡したものがそのまま使われます。
しかしGitHub Pagesに置くと、**中身をあとから書き換えられます。**

もしGitHubのアカウントが乗っ取られたら、
攻撃者はアプリを書き換えて、鍵を外部へ送る仕掛けを埋め込めます。
利用者は気づけません。次に開いた時点で新しいコードが動くからです。

**GitHubアカウントには必ず二要素認証をかけてください。**
これは公開する形を選んだ以上、避けられない性質です。

---

## 4. リンクは、送った先にずっと残ります（性質)

URLの `#` 以降がサーバーに送られないのは事実です。
GitHubのログにも残りません。ここは設計どおりです。

ただし、次の場所には残ります。

- **LINEやメールの履歴** — 送った相手のトーク画面に残り続けます
- **ブラウザの履歴** — アプリは読み込み後にアドレス欄から消しますが、
  消す前に記録されている可能性はあります
- **ブラウザの同期機能** — 履歴を同期している場合、他の端末にも渡ります

鍵を渡す以上、どこかに残ることは避けられません。
**漏れたと思ったら、共有キーを作り直す。** これが唯一の対処です。

---

## 5. 確認して、問題がなかったところ

**リポジトリに鍵は入りません**
`DEFAULTS` を空のままにしておけば、公開しても鍵は含まれません。
`.gitignore` で、鍵入りファイルの誤コミットも防いでいます。

**anon public キーが公開されても問題ありません**
このキーだけではテーブルに一切触れません。共有キーが揃って初めて届きます。

**通信はすべて暗号化されています**
GitHub Pages も Supabase も HTTPS です。

**外部のスクリプトを読み込んでいません**
アプリが外から読むのは Google Fonts のCSSだけで、
JavaScriptは一切ありません。鍵を横から読まれる経路はありません。
（Googleには、フォント取得の際にIPアドレスが渡ります。
　気になる場合はフォントの読み込み行を消してください。見た目が少し変わるだけです）

**相手から届いた文字が画面を乗っ取ることはありません**
表示する箇所はすべて無害化済みです。前回の確認から変わっていません。

# 第2部：Supabaseとの関係

## Supabaseは何をしているのか

ひとことで言えば、**ふたりの端末のあいだに立つ郵便受け**です。

```
あなたの端末                                    相手の端末
┌──────────┐                          ┌──────────┐
│ 記録（本体）│                          │ 記録（本体）│
│ 計算・表示  │                          │ 計算・表示  │
└─────┬────┘                          └────┬─────┘
      │                                      │
      │  変更を置きにいく／取りにいく             │
      ▼                                      ▼
      └──────────►  Supabase  ◄──────────┘
                    （記録の控え）
```

大事なのは、**Supabaseが主ではない**ことです。

- 記録の本体は、それぞれの端末にあります
- 計算（折半、貸し借り）はすべて端末の中で行われます
- Supabaseは、変更を預かって相手に渡すだけです

だから、Supabaseが止まっても、電波が届かなくても、
記録・計算・精算はふだんどおり使えます。次につながったときに追いつきます。

---

## Supabaseが持っている情報

| 項目 | 例 |
|---|---|
| 日付 | 2026-08-15 |
| 内容 | スーパー |
| 金額 | 4000 |
| 立て替えた人 | A / B |
| 支払手段 | PayPay / 現金 / クレカ |
| 個人分とその中身 | 1000 / 化粧品 |
| 精算済みかどうか | 済 / 未 |
| PayPayの取引番号 | （取り込んだ場合） |
| 表示名 | あなたが設定した名前 |

**入っていないもの**：メールアドレス、電話番号、口座情報、クレジットカード番号、
位置情報、端末の識別子。アプリはこれらを一切扱いません。

とはいえ、上の情報だけでも生活のパターンはかなり読めます。
機微でないとは言えないので、鍵の扱いは慎重にお願いします。

---

## 誰がその情報を見られるのか

| | 見られるか |
|---|---|
| あなたと、招待した相手 | はい（共有キーを持っているため） |
| GitHubで公開したアプリを開いただけの人 | いいえ（鍵がないので空の画面） |
| Supabaseのアカウントにログインできる人 | **はい**（管理画面から中身を見られます） |
| Supabase社の運用者 | 技術的には可能（一般的なクラウドと同じ条件です） |

3番目に注意してください。Supabaseのアカウントは**あなたのもの**です。
そのログイン情報が漏れれば、管理画面から記録がすべて見えます。
**Supabaseのアカウントにも二要素認証をかけてください。**

---

## 3つの鍵の違い

混乱しやすいので、整理しておきます。

| 名前 | 役割 | 扱い |
|---|---|---|
| **共有キー**（UUID） | 記録にたどり着くための鍵 | ふたりだけで共有。これが要 |
| **anon public キー** | Supabaseに話しかけるための札 | 公開されて構わない |
| **service_role キー** | 何でもできる鍵 | **絶対に使わない・渡さない** |
| アクセストークン（sbp_…） | Supabaseアカウントの操作用 | セットアップ後は削除してよい |
| データベースのパスワード | 直接接続する用 | ふだん使わない。控えるだけ |

アプリが使うのは、上の2つだけです。

---

## やめたくなったら

**同期だけやめる**
アプリの設定でスイッチをオフ。端末の記録はそのまま残ります。

**Supabaseから記録を消す**
SQL Editorで次を実行します。

```sql
delete from public.entries where household = '共有キー';
```

**プロジェクトごと消す**
Supabaseの管理画面 → Settings → General → Delete project

いずれの場合も、端末の記録は消えません。
アプリはこれまでどおり、ひとりで使う道具として動き続けます。

---

# まとめ：いま安全と言えるか

| 危険 | 状態 |
|---|---|
| 鍵を知らない人に記録を読まれる | 心配ありません |
| 総当たりで鍵を当てられる | 現実的に不可能です |
| 細工したリンクで記録を盗まれる | **修正しました**（確認画面が出ます） |
| データベースを埋められて使えなくなる | 前回修正済みです |
| 同じアカウントの他プロジェクトから鍵を読まれる | 置くものに気をつけてください |
| アプリを差し替えられる | GitHubに二要素認証をかけてください |

**あなたにお願いしたいのは、この3つだけです。**

1. GitHubアカウントとSupabaseアカウントに、二要素認証をかける
2. 招待リンクは、ふたりだけが見られる場所で送る
3. 心当たりのない招待リンクは開かない（開いても確認画面で止められます）
